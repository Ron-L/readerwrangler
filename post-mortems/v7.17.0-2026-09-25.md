# Post-mortem — v7.17.0 (2026-09-25)

**The one book-field table.** Released prod+dev (squash `37bca2a`, tag `v7.17.0`, branch
`feature/book-fields-table` KEPT). 2 alphas + release prep. This is the *permanent* version of the
7.16.0 fix: the deferred "one-table unification" (SERIALIZATION.md §11), executed to plan, plus the
mobile fold-in. **No user-facing change** — a pure structural/data-integrity release.

## What shipped

- **One table, `bookFields.js`.** Merged `BOOK_FIELD_OWNERSHIP` (merge classes, was bookMerge.js) and
  `WIRE_FIELDS` (pack/unpack, was serialization.js) into a single `BOOK_FIELDS` — one row per field,
  columns for BOTH merge behavior and wire mapping. A field can no longer be defined for one concern and
  forgotten for the other; that split is exactly how `genresAsOf` drifted in 7.16.0. `KNOWN_BOOK_FIELDS`
  and the merge/overridable lists derive from the table. **Drift went from test-*caught* to
  *unrepresentable*** — the meta-principle (structure over discipline) applied to the thing itself.
- **`serialization.js` retired**; its `packBook`/`unpackBook`/`roundTripCheck` + the schema validator
  moved into `bookFields.js`. `bookMerge.js` slimmed 217→92 lines: now just the merge *implementation*,
  reading the table.
- **`schemaSelfCheck()`** — the former build-time cross-check as a pure function; runs in the Node gate
  AND the localhost/version-gated in-app self-check, flagging any field that would be silently dropped
  on Save.
- **Mobile folded onto the shared unpacker.** `mapBackupBook` deleted; mobile now calls
  `unpackBook(item, { safeDefaults: true })` — the same table/unpacker as desktop. `safeDefaults` fills
  the fields mobile renders straight off the book (tags:[], userEdited:{}, coverUrl:'') so nothing hits
  `undefined.map()`. Two hand-kept mappers collapsed into one. Net across the changed core ≈ −113 lines.

## What went right

- **Test-guarded migration held green throughout.** 22 merge + (11→14) serialization/table tests stayed
  green at every step (characterization), so "behavior unchanged" wasn't a hope — it was gated. The two
  new tests cover the mobile `safeDefaults` path.
- **The mobile audit was done in source, not from memory.** Before touching mobile.js, enumerated every
  `book.`/`b.` field access and cross-checked each against `unpackBook`'s output. Most apparent
  divergences were inert (wire prices are already numbers from the desktop packer; undefined/''/null all
  hit existing falsy/`== null` guards). Only four real changes surfaced — including the one that would
  have bitten silently: the `addedToWishlist` date-sort fallback that used to live in `mapBackupBook`'s
  `dateAdded` had to move to the sort site to preserve wishlist ordering.
- **Divergence pre-flight earned its keep.** Before the push it caught that **dev/main and prod/main were
  on divergent lineages** — dev sat at the un-squashed 7.16.0 branch tip (`d0af1e3`), never got the
  squash. Root cause: a mid-7.16 dev push so Ron could test on his phone (before he remembered the Chrome
  DevTools mobile simulator works on desktop). Caught *before* any remote was touched.

## Judgment calls

1. **CHANGELOG attribution — corrected, not rubber-stamped.** Ron asked whether building the table had
   surfaced "several drifted fields" we could name in the changelog. Honest answer: **no** — the dropped
   fields (`collectionTags`, `targetPrice`, `dateAdded`, `seriesTotal`, `publicationDate`,
   `hasEnrichedData`, the `note`/`userNote` phantom) were the **7.16.0** fix, already logged there; by
   7.17.0 the two lists were reconciled and every test stayed green. Writing "7.17.0 was losing fields
   x,y,z" would have misattributed 7.16.0's work. We reframed to credit 7.16.0 for the fix and 7.17.0 for
   making it *impossible to reintroduce*. (Verify before agreeing — even with the user's own suggested copy.)
2. **dev divergence: recommended the permanent fix over the bandage.** Ron leaned option 2
   (reconcile-merge dev) and asked if I had doubts. I did: option 2 serves 7.17 to dev but *perpetuates*
   the divergence (a merge commit on the messy lineage; next release repeats it). Recommended option 3
   (a one-off `--force-with-lease` to align dev to prod's clean lineage) — **safe here** because dev is a
   disposable GitHub Pages test mirror, nothing branches off it, and every commit on dev/main was verified
   already archived in the kept `feature/orphan-cleanup-dialog` branch (zero unique commits lost). The
   never-force rule protects *authoritative/unarchived* history from loss; dev/main is neither, so a
   one-off force honored the rule's intent. Ron approved; dev/main == prod/main now. **Divergence solved,
   not deferred.**

## Process notes

Two throughlines: **structure over discipline** (the whole release makes a class of bug unrepresentable
rather than better-tested — the completion of Law 10) and **verify before agreeing** (the CHANGELOG
attribution, the mobile audit in source, the divergence pre-flight). The dev/prod divergence is the
lesson to bank: a convenience push to the test mirror created a lineage split that sat invisible until
pre-flight surfaced it — and the clean fix was to treat the mirror as disposable, not to preserve its
accidental history.
