# Post-Mortem: 7.14.3 — relay setup & restore hardening

**Date**: 2026-09-20
**Release**: 7.14.3 (app), prod+dev, 1 alpha. Two fixes: (1) Relay Setup no longer sticks in
manual-entry mode after ✕/backdrop/Done; (2) restoring a backup never silently overwrites existing
sync credentials — on a different channel it asks (keep-current default / use-backup). mobile.js
untouched.

The code was small; the *provenance* is the story: a documentation review surfaced a live, designed-
but-never-built footgun, and building it surfaced a second bug.

## How the two fixes were found

1. **The cred-mismatch guard came out of the SUPPORT-KB review.** Reviewing §15.3 ("your sync channel
   is never changed by a restore"), Ron flagged it as probably wrong. The code said the opposite:
   restore did `relayOp('setKeys', backup.relay)` unconditionally — the exact "silent overwrite"
   documented in `RELAY-CRED-MISMATCH.md` as a **known problem with a ratified fix, sitting in the
   backlog since a June scare.** So a *doc* review found a code footgun *and* its shelved solution.
2. **The manual-mode-persist bug was found mid-build.** While Ron tested the cred-mismatch confirm, he
   hit a separate bug: Relay Setup's ✕/backdrop/Done reset only `relaySetupOpen`+`section`, not
   `relayManualCreds`, so it stuck in the manual-entry form across opens. This was the *exact
   close-drift class* the dialog-dismissal audit had predicted ("no encapsulated closer for
   relaySetup"). Fixed with a `closeRelaySetup()` closer routing all three paths.

## ✅ What worked

1. **Doc review as a bug-finding instrument.** The KB pass wasn't meant to find code bugs — it found a
   serious one (silent credential revert) by making a false sentence collide with the code. "Verify
   doc claims against the code" (the 7.11.0 lesson) paid off again, this time in the *user's* favor.
2. **The backlog had the answer.** `RELAY-CRED-MISMATCH.md` was a fully-specified fix nobody had built.
   "Look backward before inventing forward" — the design was ready; we shipped it in a few lines, not
   the estimated 2-3 hours, and pruned the inline-bookmarklet nicety once we saw Relay Setup's "Load
   credentials from backup" already covers the deliberate-switch case.
3. **Right-sized override.** Ron steered from a full prompt to "mismatch-only, keep-current default,
   dismiss = keep" using the *existing* `showConfirmDialog` — no new modal, no Windows modifier-click
   (PRINCIPLES: drag/click modifiers lie on Windows), safe on dismiss.
4. **The audit predicted the second bug.** `closeRelaySetup()` is exactly the encapsulated closer the
   dialog-dismissal audit said relaySetup lacked — so the fix was already designed.
5. **The pre-build gate rode along quietly.** It fired on the version-drop edits (as it does), a mild
   tax, no drama.

## ❌ What went wrong / friction

1. **Branch-flip churn for TODO/doc edits.** The whole cycle was done on `fix/relay-restore-hardening`
   (the alpha Ron was testing), but TODO.md and the docs live on `main`. Every filing (fetcher-throttle,
   Read-in-Kindle, MegaPack, the 3 real-use finds, the release docs) meant checkout-main → edit →
   commit → checkout-back, each briefly flipping Ron's served build to 7.14.2. It worked and I warned
   each time, but it's friction. Worth a better pattern next time — e.g. a second worktree for docs, or
   batching doc edits at branch boundaries.
2. **SUPPORT-KB divergence bit the sequencing.** The KB review pass was committed to main mid-cycle, so
   the §15.3 fix had to land on main *after* the squash-merge (not on the fix branch, which carried a
   stale KB) — an extra step to avoid a squash conflict. Long-lived feature branches + actively-edited
   docs on main don't compose freely.

## 👀 Watch
- **The 3 real-use finds filed this cycle** (context-menu clip → chokepoint all menus; price-goals
  resurrect on import [data-integrity, investigate the removal→device-state→merge path]; orphan-cleanup
  import dialog). The goals-resurrect one is the priority — a deliberate removal silently reverting.
- **Restore cred behavior in the wild:** the mismatch confirm on real different-channel restores.

## Final thought
A sentence in a help doc that didn't match the code turned into a shipped fix for a silent
data-integrity footgun that had been designed-and-shelved for months. The KB review keeps paying for
itself in ways it wasn't scoped for — and "the backlog already solved it" beat "let's design it" once
again. The expensive part wasn't the code; it was the branch-flip friction, which is the thing to fix
in *how* we work next.
