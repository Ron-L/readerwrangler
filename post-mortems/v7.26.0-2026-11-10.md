# Post-mortem — v7.26.0 (2026-11-10): one logging module, Diagnostics, Restore that puts back exactly the backup

_Released 2026-11-10: squash `4fb34f7` on main, tag `v7.26.0`, pushed to prod and dev. Branch `feature/logging` kept
(alphas 1–28, 11-05 → 11-10). The design of record is `docs/design/LOGGING.md`; the codes are listed in
`docs/design/MESSAGE-CODES.md` (generated). This file folds in the notes kept during the build (`v7.26.0-notes.md`)._

## What shipped

1. **One logging module** (`logger.js`). Every message has a level (debug, info, warning, error, critical), an area
   (17 of them) and, from warning up, a numbered code used at exactly one place. An always-kept log (the last ~500
   entries, repeats counted) lives in the browser, never on the relay. The console prints exactly what's recorded.
   Every toast and every dialog goes through it, with the person's answer to a dialog, so the log reads as one timeline
   of what the person saw and what happened underneath.
2. **Two switches instead of a ladder of levels** — "Show a banner when something goes wrong" and "Also record extra
   detail" — set in the Diagnostics window or by `?errorBanner=on&logDetail=on` (Ron's idea: plain words in the
   address beat a level number).
3. **The Diagnostics window** (Help → Diagnostics…, and "Full log…" under the 🕐 history): newest first, filters, the
   details of a line, live updates, Clear, Copy diagnostics. The phone gets Copy diagnostics in its menu.
4. **Restore puts back exactly the backup** — everything except the Cloud Sync credentials (merged only after asking);
   a missing part restores as empty; a file that can't be restored is refused before anything changes, with every
   problem named at once (`backupCheck.js`).
5. **Fixes found by the work:** the false "Library repair" after an Import (two causes); the book store's saves no
   longer overlap; a library that can't load says so (desktop and phone) with its own advice; a damaged status note no
   longer stops the load; a failed drag-and-drop says so; the reset page's dead "Import amazon-library.json" route.
6. **Tooling:** the commit check for the logging rules (`tools/message_codes.py`: literal levels and known areas,
   numbered codes once each, no bare toasts, no dialog without its area); the screen-test driver fails a file on any
   error or critical line the test didn't declare; Cloud Sync in screen tests through a local relay; the version check
   reads its module list from `readerwrangler.html`.

## What went right

1. **The logging paid for itself while it was being built.** Making the after-Import check's line an error exposed the
   false repair; the driver's "no undeclared error" check exposed the storage lock (`return new Promise` inside a `try`
   — the `finally` released the lock as the write started; the fix was one word, `await`). Both had been invisible:
   a plain console line nobody read.
2. **Ron's design calls made it simpler, not bigger:** two named switches instead of five levels; the Diagnostics window
   as its own window with two ways in; "None red is fine" for refused moves; Restore's rule in one sentence (everything
   but the credentials; missing = empty; refuse only what can't be used).
3. **Every fix started with a failing test**, and the startup tests used real failures (the browser's book store made
   to fail), not planted messages.
4. **A check, not a promise:** the logging rules are a commit check, so a new message can't skip its level, area or
   code, and a toast or dialog can't skip the log.
5. **Ron's "every question carries its own context"** (11-09) made the long design rounds answerable hours later.

## What went wrong

1. **The second check for the same thing was missed** (Ron asked that this be named). On 11-05 I fixed the integrity
   check inside the load and walked past the other check of the same event — the one after an Import, added in 6.3.0 —
   though I read its code that day. And the Import tests asserted "no repair" right after the Import returned, before
   that check ran; one never asserted it at all. Law 5's class includes *every check of the same thing*, and a test
   asserts the outcome after the screen settles.
2. **Two tests passed without testing anything.** DIAG-008's first form planted a dated line, but the page's own save
   when it closed overwrote it — the test passed with no dated line on screen. IMPORT-004's first form didn't fail when
   Import's arming of the check was removed. Both were caught only by making the test's own bug happen. "Shown it can
   fail" has to mean *under the bug it exists for*, and a test checks that its own setup happened.
3. **Restore's rule was never written down before this release**, so the code drifted from the promise its own
   "restore?" box made: a backup missing a part was merged into the library. A one-sentence rule for each operation,
   written before building it, would have shown the gap.
4. **My first theory for the false repair was wrong** (an emptied book store). Law 3 held — the probe came before the
   fix — but I said the theory before measuring.
5. **Mechanical edits went wrong twice:** a `sed` by line number damaged a test file after earlier edits had moved its
   lines; the tag-delete toast lost its `{ toast: true }` in an edit and went silent (found and fixed during the build,
   not by any test; every call switched to a new area was then scanned for the same slip). Edits go through the Edit tool, by text, not by line number.
6. **A hand-kept list drifted again:** the version check's list of modules missed `logger.js`, so its cache-buster was
   never checked. Now read from `readerwrangler.html` (Law 4: a list kept by hand drifts).
7. **One screen test flaked once** (test_boot.py: the File menu not found right after BOOT-001). Not reproduced in the
   next runs; filed in TODO, to be read, not re-run past (TESTING.md §7).

## The bug no test would have caught

The tag-delete toast that lost `{ toast: true }`: the log still recorded the line, so no test and no check noticed
that the person no longer saw it. **Written (Ron's yes, 2026-11-10):** `test/ui/test_tags.py` — TAGS-001 (one tag) and
TAGS-002 (two ticked tags) check that the receipt is on screen, on top and readable; both were seen to fail with the
receipts' `{ toast: true }` removed (served to the browser changed, the file untouched). The class — one such check
per area's main confirmation — is filed: TODO "Receipts reach the screen: one screen test per area, not only the log"
(after Faster loading).

## Laws touched (proposed — PRINCIPLES.md)

- **Law 5:** the class includes every *check* of the same event, not only every copy of the code (the two integrity
  checks).
- **Law 3 / TESTING.md §6:** "shown it can fail" means under the bug it exists for — remove the fix, or make the bug
  happen — and a test asserts that its own setup is there before it asserts the outcome (DIAG-008, IMPORT-004).
- **Law 11:** an operation's rule in one sentence before it's built — what it keeps, what it replaces, what it refuses
  (Restore).
- **Law 12:** a message nobody can see is no message — the always-kept log, and the driver failing on an undeclared
  error, are the mechanism (the storage lock, the false repair).
- **Law 4:** a hand-kept list drifts (the version check's module list) — derive it from the source.
