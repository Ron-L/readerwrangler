# Post-mortem — v7.16.0 (2026-09-22)

**Data-integrity hardening.** Released prod+dev (squash `27af54e`, tag `v7.16.0`, branch
`feature/orphan-cleanup-dialog` KEPT). ~11 alphas in one long session. Headline user fix: **Save/Restore
was silently dropping library data; it's now field-complete.**

## What shipped

Started as "orphan-cleanup dialog," became a data-integrity release when the dialog work exposed the
merge/serialization layer:

- **Merge-completeness chokepoint** (bookMerge alpha.2): every book field carries an *explicit* merge
  decision; `KNOWN_BOOK_FIELDS` derived from `BOOK_FIELD_OWNERSHIP`. No more silent "unlisted →
  incoming-wins" default (exactly how `orphanStatus` had defaulted wrong).
- **`collectionTags`/`collectionTagSeen` → user-owned** (alpha.3): were `'amazon'` (incoming-wins) and
  wiped on every import. Confirmed live (1470→0).
- **Sticky `orphanStatus`** (alpha.4): freshness-guard — newer `orphanCheckedDate` wins; a stale echo
  can't clear a flagged orphan.
- **Serialization unified** (alpha.6-9 + cross-check): the real bug. `exportBackup` was a **drifted
  duplicate serializer** 8 fields behind `buildDeviceStatePayload`, and the unpacker read fields the
  packer never wrote (and vice-versa). Fix: ONE `WIRE_FIELDS` list → ONE `packBook` + ONE `unpackBook`
  (serialization.js), triple-guarded (dev test + build-time cross-check + localhost self-check). Pre-2.0
  `amazonData` backups refused honestly.
- **Orphan dialog built then reverted** (alpha.1 → revert `1125893`): deferred to its own branch, to be
  rebuilt on this release's durable `orphanStatus` + serialization. Preserved in `914025b` +
  docs/design/ORPHAN-CLEANUP.md.

## Mistakes made

1. **Fixed before reproducing.** I shipped the `collectionTags` fix (alpha.3) on code analysis alone,
   before ever reproducing the wipe in the running app. Ron: *"It is ALWAYS worth verifying a bug before
   fixing so we KNOW we have a good test case to use to test the fix."* After that, **every** fix followed
   repro → fix → verify with console scriptlets against the real IndexedDB. (Reinforces Law 3.)
2. **Extended scope past what was asked.** Ron approved "detect & refuse" for legacy files; I went further
   and *removed* legacy support entirely, baking it into the design doc without asking. Ron: *"do please
   ask in the future. That was a step further than what I said."* (Reinforces Law 1 / STOP-and-ASK.)
3. **Added a vestigial field to the wire.** I put `genresAsOf` in `WIRE_FIELDS` because the old packer
   wrote it — but 7.15.3 had deemed it dead and excluded it from `KNOWN_BOOK_FIELDS`. The field-schema
   validator flagged it live on Ron's restore. (My miss; the chokepoint's win — see below.)

## What went right

- **A chokepoint caught the next chokepoint's bug.** The 7.15.3 field-schema validator flagged
  `genresAsOf` the instant serialization produced it. Mechanism over discipline, working as designed.
- **The bisect found the real cause.** Ron's Save→probe→Restore→probe bisect isolated the loss to the
  *restore* side, and tracing found `exportBackup` was a separate, drifted serializer — not the one I'd
  patched. The "shared with exportBackup" comment was stale and I'd trusted it (NEVER ASSUME).
- **Triple guard.** Dev test + build-time cross-check (`WIRE_FIELDS` ⟺ `KNOWN_BOOK_FIELDS`, both
  directions) + a localhost/version-gated in-app self-check over the real library.
- **repro → fix → verify** became the rhythm and caught issues before they shipped.

## Deferred (with homes)

- **One-table unification** (the next big thing): merge `BOOK_FIELD_OWNERSHIP` + `WIRE_FIELDS` into one
  `bookFields.js` per-field table → drift becomes *structural*, not test-caught. docs/design/SERIALIZATION.md §11.
- **Mobile** folds into that: `mapBackupBook` → `unpackBook(item, {safeDefaults})` + one `reviewCount`→
  `ratingCount` render + a mobile audit/test. (§11.)
- **Orphan feature**: its own branch on this durable foundation (`914025b` + ORPHAN-CLEANUP.md + the dev
  injector, all recorded in memory).

## Process notes

Ron's two corrections — *verify the bug before fixing* and *ask before extending scope* — are the
session's throughline, and both are now reinforced in PRINCIPLES (Laws 3, 1). The completeness-chokepoint
pattern (make the missing decision impossible, don't just document it) proved itself twice in one release.
