# Post-mortem — v7.21.2 (2026-10-16)

**The Date Added filter follows the calendar.** Released prod+dev (squash `0bcb677`, tag `v7.21.2`, branch
`fix/date-filter-years` KEPT). Three alphas + a tooling commit.

## What shipped

- One shared piece (uiHelpers.js) for the Date Added choices, ranges and labels on computer and phone. It replaced
  3 copies of the range math, 4 drifting label copies (two printed the raw "year2025") and a hand-typed year menu that
  would have gone stale every January 1. **This year / Last year** roll with the clock (Ron).
- **Earlier year**: one small dropdown listing only the years the library has, newest first (alpha.3).
- `COPYRIGHT_YEARS` = "2025, 2026" — a LIST, not a range, so a skipped year isn't claimed (Ron's correction, alpha.2);
  the version-guard refuses the first shipped-code commit of a new year until the year is appended.
- Tooling: the pre-build gate now bounces the WHOLE batch (see below).

## What went right

- **Ron's grep for "2025" found a class, not a line.** One hard-coded year led to the 4 label copies + 3 range copies;
  centralizing made the year menu, the phone and the saved-Search label honest at once.
- **Ron's two design corrections were both better than mine:** "This year means *this* year" (roll, don't freeze), and
  a list of years rather than "2025–2026".
- **Real data caught the design flaw in one look** (Law 8): alpha.1 listed every year the library has — on Ron's
  library that ran back to 2001, a 25-line menu. The fix (one compact dropdown) came from Ron's "this looks silly".
- **A mechanism the same day the lesson recurred.** The gate's batch trap struck twice in this release; Ron said
  "cut that off at the pass NOW", and the whole-batch bounce was built, simulated and committed before release.

## What went wrong

- **The batch trap, twice more** (alpha.2 About edit, alpha.3 version stamp) — despite the memory note "send the first
  edit alone". Third and fourth occurrences of a documented lesson: the meta-principle again (only a mechanism works).
- **alpha.1 didn't think about the length of a list built from user data.** "Only years the library has" sounded
  bounded; it isn't, for a 25-year Kindle owner. A list whose length comes from the user's data needs a control that
  stays small at any size.
- **The new 5-second batch window bit on its first real use.** During the release, the re-send of the bounced edit
  arrived inside the window and was refused again (fail-safe — nothing lost — but a wasted round). Ron spotted the
  root problem the same turn: a timer is a guess at "same batch". **Found:** every tool call in one batch carries the
  same message id in the session transcript, so the batch has a real identity the hook can read. Converting the gate
  to it is pending Ron's go-ahead (one probe first: confirm the hook receives the tool-call id and that the transcript
  already holds the message when the hook runs).
