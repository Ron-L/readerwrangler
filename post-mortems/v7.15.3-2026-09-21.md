# Post-Mortem: 7.15.3 — the two 7.14.4 import-merge follow-ups (1A decided-against, 1B built)

**Date**: 2026-09-21
**Release**: 7.15.3 (app), prod+dev, 4 alphas (one a throwaway). Two follow-ups filed after 7.14.4:
1A (route merge "branch 2" through `mergeBookFields`) and 1B (kill the phantom/misnamed-field class
beyond the merge). **1A: decided against after grounding, documented. 1B: built as a dev-only runtime
field-schema validator.** No user-facing behavior change (dev-gated; inert on prod). CHANGELOG carries
an honest "Under the hood" note.

## The story — two assumptions corrected before code
**1A** looked small ("Small, ~1–2 alphas"). Reading the actual code first flipped it: branch 2 already
routes its user-owned cluster through the registry (`assignUserOwnedFields`), so the "no field list
outside the registry" goal was *already met*; and `mergeBookFields` is **incoming-as-base** while branch 2
needs **local(owned)-as-base** (the incoming wishlist dup is product-page-scraped, often less complete).
Unifying would mean a whole second merge mode for a rare path, at regression risk. Recommended **against**;
Ron agreed; documented the decision in `storage.js` + TODO so it isn't re-attempted.

**1B** was the bigger correction, and it was *mine to eat*. When I filed it after 7.14.4 I'd framed
"field-name constants everywhere" as *the* way to kill the name-mismatch class. Ron's question —
"any misses will show up as syntax errors, right? so large scope but low risk?" — forced the check I
should have done first: **in plain JS, `F.TYPO` silently returns `undefined`** (same silent failure as
the phantom-field bug), so constants without a `Proxy` are large-scope AND real-risk, and even then a
runtime **schema validator** catches more for far less churn. We changed the plan to the validator:
`KNOWN_BOOK_FIELDS` + `unknownBookFields()` in `bookMerge.js`, generalizing the "no-invented-keys"
invariant from the merge to whole book objects; a dev-only `console.warn` (dev + dev-repo) plus a
**localhost popup**; four new gate tests (17/17).

## ✅ What worked
1. **NEVER ASSUME, four times, all caught by verifying** — (a) 1A "small unify" → actually already-done +
   risky; (b) my own "constants prevent the class" overclaim → plain JS doesn't enforce it; (c) branch-2
   metadata semantics → read, not guessed; (d) the field set → enumerated by a subagent across
   fetchers/normalize/merge/storage/setters, not from memory. The rule codified yesterday is doing real work.
2. **The enumeration paid off**: the validator was **clean on the real 3183-book library first run** — no
   false positives — which means the compiled field set was complete. The dev-warn/popup also self-calibrates
   (any future warn = add a legit field or catch a real phantom).
3. **Honest pushback on my own prior filing.** The best outcome of the day was *not* building the large
   thing I'd oversold. Ron's one question saved a big, risky, low-value conversion.
4. **Verified the popup live** with a throwaway alpha (dropped `title`, saw it fire, reverted) rather than
   asserting it works.

## ❌ What went wrong
1. **I oversold "constants everywhere" when I filed it (7.14.4).** I asserted a mechanism would "kill the
   class" without verifying the mechanism actually *enforces* anything in plain JS. That's a NEVER-ASSUME
   miss one layer up: not "is this fact true?" but "does this *solution* do what I claim?" Lesson added to
   PRINCIPLES: a proposed safeguard's guarantee must be verified against the language/tooling before it's
   sold as one.

## 👀 Watch
- **`KNOWN_BOOK_FIELDS` completeness** — if a genuinely new book field is added later, the dev-warn/popup
  will flag it until it's added to the set. That's the intended self-calibration, not a bug.

## Final thought
The day's most valuable work produced almost no shipping code for 1A and a dev-only tool for 1B — because
the real output was *catching two of my own assumptions before they cost anything*: an approved task that
wasn't worth doing, and a mechanism I'd sold that couldn't deliver. NEVER ASSUME earned its place at the
top of the rules by being the thing that kept paying, again, all day.
