## What shipped

1. **The Delete key acts on the selection**, by the one table's first rows (`gestureTable.js`; `ONE-TABLE.md`, approved
   by Ron): several folders = one question listing them, one Undo; books and folders together = both, one question,
   one Undo; nothing selected = nothing; the Inbox says it can't be deleted; right-click Delete acts on all the selected
   folders. Undo restores exactly and returns you where you were; Redo after Undo redoes exactly that delete.

   boxes say "the next time you update your library from Amazon".
3. **Tooling:** the relay tests start and stop their own local relay, stopping only processes proven ours by exact id
   (never `/T`) and checking the ports; `run_tests.py --release` fails on any skipped file; the backlog report reads
   `done <id>` from every branch.
4. **Every repository's own `.gitignore`** keeps secrets out (the standard block); `Projects/check_gitignores.py`.
5. **Documents:** Law 21 (a button names what it does); the glossary is the one list of words (CLAUDE.md points to it;
   "fetcher" retired); TODO filings (the button sweep, one process starter, the `skip:` line, the anti-glossary, a
   glossary page).

## The trial — autonomous mode (Ron, 2026-11-12)

**Set up:** the rules in CLAUDE.md ("Autonomous mode") and the Projects-root exception; the switch `.private/AUTONOMY.md`
(trial: four tasks); the record `.private/PROGRESS.md`, `REVIEW-QUEUE.md`, `REVIEW-DONE.md`; `main-prime`, the waiting
branch. **Ran:** 09:58 → 11:25 for the four tasks (three agents, one at a time in the folder; the `.gitignore` task by me);
two more rounds the same afternoon from Ron's verdicts (books and folders together; the wording).

**The measure — how often Ron reversed a decision:** 35 decisions answered in the queue — **33 kept** (several built
on: Q-010 became Law 21, Q-020/022/024 a task, Q-021 a testing convention), **1 where he chose my proposed alternative**
(Q-013), **0 reversed**. Three entries came back asking for clarification (Q-026, Q-033 — too terse; Q-032) — the
"every question restates its context" rule held in the conversation but slipped in the queue's later entries.

**Ron's verdict on the trial (afterwards):** wading through 36 questions was tedious and exhausting — the terse ones
most — and he didn't need to review the vast majority (0 reversals says the same); the Delete fix grew as the agents
fixed what they found. But done the old way, one at a time, the same decisions would have cost half a day more. **The
fix:** a profile of how he decides (`.private/RON-PROFILE.md`) — I predict and act, and only what it can't predict,
what's costly to reverse, new words people see and anything outward-facing reach him, each with my prediction; the
rest goes in a decisions log he may ignore. And a scope line: fix what's quicker to fix than to write up, in human
terms; file the rest.

**What made it work:** Ron answering in the file, in batches, while the work went on; the reviews — every agent's diff
read and its tests re-run by me before anything entered `main-prime` (an agent's "done" is a claim); the record in
files, not in my context.

**What the trial found:**
1. **Claude Code's auto-mode safety check is a second line of defence** — it refused a CLAUDE.md edit
   ("self-modification") and the public pushes ("create public surface") until Ron said so *in the conversation*; a
   verdict written in the queue file doesn't count to it. So outward-facing steps need his word in the chat (the phone
   works — Remote Control, set up today).
2. **Agents can't work in their own copies of the repository yet** — the build tools, the test browser and the name
   check's tools are installed locally, not in git (Q-004) — so ReaderWrangler tasks ran one at a time in the folder.
3. **Usage limits:** an open session resumes by itself after a reset, three times in a row; I can't read the usage
   numbers myself (no documented way). For a week away: the PC stays on, Windows Update paused, Ron's phone nudges it.

## What went right

1. **The reviews caught what the agents didn't:** `taskkill /T` in the relay stopper could take an unrelated process
   whose dead parent's id the relay had reused — fixed to stop only proven processes by exact id; the text-box guard
   checked before trusting the new Delete path; the book/folder delete restructuring traced for equivalence with every
   existing caller (the drag onto the Trash has no screen test).
2. **Tests first, every time** — TABLE-001–010, DELKEY-001–016, RUN-016–024, BKLG-015, each shown failing first (or on
   a deliberate break) — and the first release run with `--release`: 35 files, nothing skipped.
3. **Ron's questions turned into structure:** "where is our agreed terminology?" exposed a glossary nobody pointed to,
   a header that claimed a page that didn't exist, and an undecided word ("fetcher") all over the help; his anti-glossary
   idea turns the "words we don't use" into a visible list a commit check reads.

## What went wrong

1. **My slip: `main-prime` made before the CLAUDE.md commit** — the first agent's branch lacked the Autonomous mode
   section ("CLAUDE.md changed on disk" gave it away); fixed by a fast-forward and a merge, nothing rewritten.
2. **My slip: the `.gitignore` script didn't skip ReaderWrangler** — it matched the repository by its `origin` remote's
   name, and ReaderWrangler has none (its remotes are dev and prod); the commit landed on `main-prime`; copied to main.
3. **My slip: the check script's first version mistook this PC's ignore file for a repository's own** — it split git's
   answer at the first colon, which in `C:\…` is the drive letter. Caught because its result was implausible
   (readerwrangler-private passing with no Claude line); my first fix was wrong too (`-z` needs `--stdin` — git said so).
4. **The backlog report counted three finished tasks as dropped** — `done <id>` read from main's commits only; the
   release's squash hides it (the same trap the ✅ marks fell into, BKLG-001). Caught because "done" went DOWN on a day
   two tasks were finished.
5. **Queue entries too terse** (Q-033): new wording listed without saying where it appears or what was asked.

## The bug no test would have caught

The backlog report's undercount (4) — it passed every test, and only a number moving the wrong way gave it away. Now
BKLG-015 pins the real cases. The general lesson is in Law 5 below.

## Laws touched (PRINCIPLES.md)

- **Law 21 (new, Ron's rule):** a button names what it does — never OK, Yes or No.
- **Law 5:** a squash hides EVERY kind of evidence a branch held — ✅ marks and `done <id>` markers alike; anything that
  reads history reads every branch. And `taskkill /T` is a pattern, not an identity (it follows parent ids Windows
  reuses).
- **Law 12:** a header that describes a page is a claim too (GLOSSARY.md "built from this list" — no page existed); an
  agent's "done" is a claim — the orchestrator reads the diff and re-runs the tests.
