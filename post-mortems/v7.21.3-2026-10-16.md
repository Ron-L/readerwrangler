# Post-mortem — v7.21.3 (2026-10-16)

**Add Bibliography to Wishlist: every author-page tab, Kindle only, in the language you choose.** Released prod+dev
together (squash `5d0b205`, tag `v7.21.3`, branch `fix/bibliography-fetcher` KEPT). Bibliography fetcher v2.1.0, nav
hub v2.2.0. One alpha, tested by Ron with the LOCAL bookmarklet on John Marrs (All Books) and P. Djèlí Clark (Home).

## What shipped

- The bookmarklet menu recognizes author pages with or without the name in the address.
- The fetcher no longer reads the page. It loads the All Books page's grid settings in the background and makes
  Amazon's own filtered request (Kindle + language, 16 per page), behind a one-question panel (Language, "Kindle books
  only.", live count). Books now carry `binding: 'Kindle Edition'`.
- About 280 fewer lines (page scrolling, "Show More" clicking, card reading — all gone).

## What went right

- **A one-line TODO opened onto the real bug.** Ron's "if we can fix it, do it" plus his question "why are so many
  physical books leaking in?" led straight to the cause: the page-reading path computed `isKindle` and never used it
  ("we'll check later" — nothing did). The one-line menu fix alone would have shipped the leak to two more authors.
- **Probe before build, in Ron's own browser, six small rounds.** Each probe answered one question and printed only
  names and counts — never cookies or account data. They found: the settings live in one `var config` (not a script
  with plain JSON), the format filter only works with a language, no-format answers carry no details, and Amazon
  details only the first 16 books of a page. Every one of those would have been a broken alpha.
- **Ron's "I don't trust page scraping"** set the direction; the rewrite deleted more than it added.
- **An offline run against a fake Amazon built from the probe results** caught nothing — but it meant the first live
  test passed in full.
- **The message-id gate passed its first live test** during the release (a fast re-send went straight through).

## What went wrong

- **I misread the fetcher at first** — told Ron "Kindle-only is already built in, always on", from the backup path's
  check, without seeing the main path never applied its own. Ron's leak question exposed it within minutes. The tell
  was a comment promising later work ("we'll check later"): a promise in a comment is not code. Law 2 — read the path
  that actually runs, not the one that looks right.
- **I put Amazon's inner workings in the public repo** (a reference note on the request), contrary to the January
  decision that moved the Amazon notes to `.private/`. Caught before any push; the branch's two local commits were
  rebuilt without it, so no reachable history ever held it. Rule now in CLAUDE.md: Amazon internals stay in `.private/`.
- **The dev-first rule was worded too broadly** in CLAUDE.md ("navigator/bookmarklet link changes"). Ron clarified:
  only changes that differ per environment (what LOCAL / DEV / PROD do differently). Reworded.
- **CLAUDE.md pointed at a folder that no longer existed** (`docs/api/`, gone since `ae276ea`). Fixed.
