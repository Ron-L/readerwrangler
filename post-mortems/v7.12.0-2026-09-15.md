# Post-Mortem: 7.12.0 — the release that fell out of a shopping trip

**Date**: 2026-09-15
**Release**: 7.12.0 (price snapshot at goal-set + Price When Set column, Goal Met rename with
trash-excluded count, format synonym healing, Show-Columns label dedup). Five alphas, all
field-tested same-session; **discussion → released in ~4 hours of wall clock**. Policy note:
per Ron, post-mortems are now ALWAYS — an uneventful release is still process data.

## Origin: usage IS the requirements pipeline

The feature came from Ron *using* RW mid-KB-review: a $0.99 series buy → "is this a bargain
or the everyday price?" → a misread savings display → the discovery that no stored field
answers the question ("what will it cost when the sale ends?") → Ron's decisive argument that
Amazon list prices are theater (a $1.99 Kindle sale "marked down" from a $17.99 *print* list),
overturning Claude's armchair "listPrice covers 95%" claim. The KB review produced doc edits;
the *usage during* the review produced a release. Both tracks ran without blocking each other.

## ✅ What worked

1. **Discussion-first caught the design trap before code existed.** The capture-policy
   question ("see a deal today → goal it today" would snapshot the SALE price) was resolved
   in conversation — capture-every-set *with the visible date* — along with the
   single-snapshot-never-a-history boundary and the label bikeshed ("Goal Met", singular,
   per-book predicate grammar). Zero rework alphas on semantics.
2. **Chokepoint at birth, carriers up front.** `applyPriceGoal` unified record+mutate+
   dialog-sync for all six goal-set sites in alpha.1, and the carrier sweep (backup ×2,
   import ×2, storage merge ×3, mobile) shipped in the same alpha — the OWNERSHIP-MODEL
   carrier-checklist scar, applied preemptively. Result: zero carrier bugs in testing,
   first release where persistence "just survived" everything on the first pass.
3. **The comb rules held.** priceTrigger enumeration (42 references, 6 writers) matched the
   recordPriceGoal caller list exactly — coverage claimed WITH the site map, per the
   three-rules doctrine.
4. **Opportunistic fixes rode cheaply**: the Show-Columns duplicate label map (found by Ron's
   screenshot within minutes) was *removed*, not fed; the Kindle/"Kindle Edition" split got a
   synonym-normalization section in FORMAT-POLICY including the REJECTED
   spelling-as-wishlist-tell idea — the invisible-encoding doctrine (Law 16 family) reused to
   win an argument Ron then conceded gracefully.
5. **Release-early, mid-review.** The KB review paused for nothing; doc commits live on main,
   the feature branch merged around them. "Wait for whatever falls out of review" was
   considered and correctly rejected — review fallout becomes its own small branch.

## ❌ What went wrong

1. **The Set-Content violation — transport class, bite #4.** A lazy one-line version bump via
   PowerShell `Set-Content` (the exact banned transport) rewrote line endings CRLF.
   Self-caught this time (the mechanical-honesty rule fired as *detection*), verified no
   content damage, normalized byte-exactly. Lesson unchanged and now absolute: Edit tool
   only, INCLUDING one-line version stamps — convenience is how the rule dies.
2. **The blank column label — the release's own sermon, unheeded.** The new column's
   Show-Columns checkbox was nameless because a duplicate label map existed to forget —
   the exact one-fact-two-places drift class this very release preaches against (and fixes,
   twice). The duplicate predated us; the miss was not *scanning for consumers* of
   COLUMN_CONFIG when adding an entry. Comb corollary recorded: when extending a registry,
   grep for OTHER places that enumerate its keys.
3. **Armchair data-model claim.** "listPrice covers 95% of the need" was asserted from field
   names, not from how Amazon actually populates them; one concrete example (The Other
   Valley) demolished it. Verify-don't-assume extends to *claims about a vendor's data
   semantics* — the field existing is not the field meaning what its name says.
