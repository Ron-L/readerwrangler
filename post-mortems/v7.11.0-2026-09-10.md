## The unifying theme: an audit is only as good as its pivot

The release began as "add action toasts" and became a coverage campaign, because each test pass
found bugs the *previous* audit had been structurally blind to:

- The alpha.4 audits pivoted on **artifacts** (`recordAction` calls, `showToast` calls,
  `saveBooksToIndexedDB` sites). Ron's Tag-Manager rename (Adult→Mainstream) exposed the blind
  spot: a tag rename mutates the tag *registry*, not the books array — no audited artifact
  anywhere near it — AND Ctrl+Z sailed through the dialog to the global stack.
- The second-generation audit pivoted on **the persistent stores themselves** ("what survives a
  refresh, and who writes it") and on **the dialog roster × live shortcuts**. That pivot found:
  the whole rename class (10 silent sites across 4 object types), Search create/delete/reorder
  gaps, three dialogs missing from the modal guard entirely (Relay Setup, Duplicate Review,
  Tags from Collections), Ctrl+A/Alt-nav/Esc-clipboard leaks, and six imperative dialogs
  invisible to React's guards.

**Law-shaped takeaway**: enumerate the class from the *state*, not from the code you already
instrumented — the stores are enumerable from the storage layer; grep-ping the UI finds only
what the UI already admits to.

## ✅ What worked well

1. **The design dialectic ran with genuine reversals in BOTH directions.** Status-History undo:
   I argued "allow" (a receipts list is undo's natural companion), Ron argued keystroke scope
   consistency — Ron won, and his "fenced for consistency" *collapsed the whole fence/block/allow
   taxonomy into one rule* (every dialog is fenced; a dialog that records nothing yields the
   info toast — no policy left to get wrong). Reorder undoability: Ron worried coverage causes
   surprise undo; the convention argument (gaps, not coverage, cause mis-undo) convinced him.
   Transactional dialog: I pushed back with the rating-instant convention and a formal
   consistency test; Ron's context-keying rebuttal (users key semantics off interaction context,
   not field identity) plus the OWNERSHIP-MODEL §4 precedent turned me — ratified as 7.12.0,
   principle recorded in UNDO-MODEL. Disagreement functioned as design QA, exactly as the
   CLAUDE.md rule intends.
2. **Chokepoint discipline, per Ron's standing directive** ("one place controls the behavior of
   an operation"): `attachDialogDismiss` (one dismissal chrome for six dialogs), five rename ops
   covering ten call sites, `moveItems` learning trash-source-means-restore so every current and
   future drag path inherits it, the DIALOG_POLICY registry driving fence + all key guards from
   one list. New dialogs and new rename surfaces now can't get the behavior wrong without
   visibly bypassing the chokepoint.
3. **The mining discipline was born and immediately earned its keep**: Ron caught that usage
   lessons were dying in chat scrollback ("GPT notes"); WORKFLOW-PATTERNS.md gained three
   sections the same day (ownership correction, the delete-at-source truth path, Book Lists as
   mobile filters) — and the truth path was **validated live within hours of being written**,
   by its own subject. Memory rule installed so the discipline survives compaction.
4. **Support answers stayed code-grounded**: the tombstone-revive semantics
   (relay-client.js:884) and the orphan-scan-is-always-full fact were verified in source before
   answering — the second one *correcting a claim I had already written into the doc from
   assumption*. The delete-warning copy survived scrutiny because the code said it should.
5. **Same-day turnaround held for all nine alphas**: every test-pass finding (trash-drag
   membership bug, the CRITICAL Ctrl+X leak, silent All-Books keys, dim-collision on cut) was
   diagnosed, fixed, and re-tested within the day, with Ron's notes quoted back verbatim per
   his request.
6. **Ron's field instincts kept out-designing the implementations**: the dim-collision catch
   (cut 0.5 vs hidden 0.4 — "dim is already taken") was a Law-16 violation sitting in shipped
   code since 5.0; the "Ctrl+C works in-dialog but Ctrl+Z reaches behind it" scoping critique
   produced the release's central rule.

## ❌ What went wrong

1. **Enumerate-all-instances failed twice more — *during an audit-themed release*.** The
   All-Books DEL fix covered the keyboard and missed the context-menu Delete (same operation,
   second site; alpha.8). The trash-drag bug was the *third* unwired path of a fix made twice
   before. The honest reading: site-enumeration keeps failing as a manual practice; the durable
   counter is the chokepoint pattern (one implementation, N thin call sites), which this release
   applied broadly. Where a chokepoint exists, the class can't reopen.
2. **A doc claim written from assumption**: "must be a FULL fetch — incremental can't prove
   absence" went into WORKFLOW-PATTERNS without checking the fetcher; the orphan scan is always
   a full pass (Phase 5, every run). Caught within the hour only because Ron asked how to force
   a full fetch. Verify-don't-assume applies to *documentation claims with operational
   consequences*, not just code opinions.
3. **Version-number drift caught late**: nine alphas of minor-release content rode a patch
   number until CHANGELOG review, forcing a same-day renumber (7.10.1→7.11.0) and a cascade of
   reference fixes (the transactional dialog moving to 7.12.0). Cheap this time; check semver
   fit when the *scope* grows, not when the release ships.
4. **One ORGANIZER_VERSION bump missed** (alpha.3 shipped stamped alpha.2) — the exact
   Help/About-provenance failure the versioning rule exists to prevent; recorded in the alpha.4
   commit, clean thereafter.
