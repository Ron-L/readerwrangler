# Post-mortem — v7.28.0 (2026-11-11): the logging as its own kit, and Send a test message

_Released 2026-11-11: squash `36fa3b6` on main, tag `v7.28.0`, pushed to prod and dev; readerwrangler.com and the dev
site checked serving 7.28.0 — the page, the built app, the settings file, the logger (with its new label setting) and
the built Diagnostics window; the old `logger.js` address gone (404). Branch `feature/logkit` kept (alphas 1–5, plus the
tooling commit `03d218b` before them)._

## What shipped

1. **Send a test message** in Help → Diagnostics…: one error marked TEST (UI-07) down the real path — the window shows
   it, the banner shows it when its switch is on, a note says so when it's off; never the critical box. Fixed wording
   on purpose (Ron): support recognizes it, and nothing a person types reaches the log.
2. **The logging as a kit in `logkit/`** that knows nothing of ReaderWrangler (`logkit/README.md`): the module
   (`logger.js`), the Diagnostics window (`diagnostics-window.js`, JSX built into `dist/logkit/`, handed the logger, the
   app's `<Dialog>` and the build line), and the commit check's general half (`check_messages.py`). RW's side:
   `logkit-settings.js` and `tools/message_codes.py` on top (Ron's shape: RW's checker does RW's checks, then calls the
   kit's).
3. One code changed (Copy diagnostics' "couldn't be copied": UI-06, was SHARE-01); a hidden secret shows as the host's
   label (ours stays "[passphrase]"; the kit's own is "[hidden]").
4. Tooling: one answer to "is this file shipped?" (`git-hooks/shipped_paths.py`) for the gate, the version guard and the
   style build; the build compiles the window; the name check covers it and honors `/* page-global */`.
5. Filed: secret patterns (hide a secret by its shape — an old or pasted Cloud Sync Key) in the Cloud Sync Key task;
   the once-failed start-up screen test in 👀 Watching.

## What went right

1. **The tooling came first, with tests that it covers the folder** (the plan Ron approved): the shared "shipped" rule
   (SHIP-001–003, two shown failing under the old rules) landed before a single file moved — so the gate, the version
   guard and the style build all saw `logkit/` from the first alpha.
2. **Every existing logging test passed unchanged through the move** — the test file combines module + settings exactly
   as the pages do, so the 34 logger tests and 9 Diagnostics screen tests stood as the proof nothing a person sees moved.
3. **The "knows nothing of RW" claim is a test, not a hope**: LOG-036 (the module), LOG-037 (the window), MSG-022 (the
   checker) — each shown failing on the code as it was ("still mentions rwLog", eight words in the old checker).
4. **Ron's questions improved the design twice.** "Can RW's checker sit on top and call the kit?" gave the two-layer
   checker. "What rule recognizes a secret — shouldn't it be a pattern?" exposed a real hole: the cleaner hides only the
   *current* passphrase, so an old or pasted key would reach the log — filed against the Cloud Sync Key, whose shape it
   needs.
5. **The release ran every tier**, including the relay tests against a temporary local relay (59 + 22).

## What went wrong

1. **The commit's style check crashed on the first file in a folder.** It copies the staged pages and scripts into a
   scratch folder to build the stylesheet, and didn't create subfolders — `logkit/logger.js` had nowhere to go. The
   tooling commit's site map had covered what the rules *say* (the gate, the guard, the style build's file list), not
   every place that *handles a path*. The hook caught it on the first commit; BUILD-008 holds it.
2. **A silent hole, found only by reading first.** The code checker found calls by the text `rwLog.log(`. The moved
   window gets the logger handed in as `log`, so its two messages would have dropped out of the support table with no
   error at all. MSG-020 holds it. Same class as item 1: a check keyed to a name or a place goes quiet when the code
   moves.
3. **A test file's own tally was wrong** — the message-code tests printed "19 passed" while 21 had run (a hard-typed
   "+ 4" for the extra checks). Now counted.
4. **My report said the build line goes "on top" of Copy diagnostics; it goes second.** Ron caught it from his paste.
   Describe the output after looking at it.
5. **Stopping the local relay didn't stop it.** Ending the shell that started it left `workerd` and three node
   processes serving the port; caught only by checking the port afterwards, then stopped by exact process id.
6. **"Every tier passes" nearly meant "every tier that ran."** The release run reported "31 passed, 2 skipped" as a
   success — the relay tests skip without a local relay. Caught by reading the summary line, not by the runner.

## The bug no test would have caught

The silent hole (2): a checker that stops seeing some calls passes every commit — nothing fails, the table just gets
shorter. MSG-020/021 now pin that the window's calls are found; the general guard is the kit's own codes listed in the
table (UI-02…07), which a vanished row would show — but only to someone reading it. Filed instead for the two process
gaps (5, 6), where a mechanism can know: the runner starts and stops its own local relay and checks the port, and a
release run counts "skipped" as failed (TODO "Turn more of our working rules into automatic checks", items 3–4).

## Laws touched (PRINCIPLES.md)

- **Law 5 (enumerate the class):** moving code is a class change — everything that keys on its *place or name*: the
  pages' script tags, every checker's file list and patterns, every step that copies files somewhere else.
- **Law 12 (mechanical honesty):** a stop isn't done until it's verified (probe the port); a report of "passed" must
  not include "skipped"; counts are counted, not typed.
