# Post-mortem — v7.24.0 (2026-10-20)

**Tag from Collections shows everything Apply will do at once. Tag names are exact text everywhere in the app. Undo
removes a tag it created.** Released to prod and dev as squash `26f17e0`, tag `v7.24.0`; the branch `fix/tfc-clarity`
is kept. The work ran 2026-10-16 → 10-20 as alphas 7.22.1-alpha.1–3, plus alpha.4, which was only a merge.

It started as a TODO-review "quickie": *"clear up the checkbox vs. preview confusion"*. Ron's alpha.3 test round was
then decided topic by topic, and that work was filed as the TODO "Tag from Collections, round 2" instead of being built
into this release (Ron: "declare that part done and log the rest").

## What shipped

1. **Tag from Collections v2.**
   - One click target per row.
   - Every book that will change is listed, in aligned columns: + add / ✓ has it / − remove. Clicking a + skips that
     book.
   - Each collection says which tag it lands on.
   - The button carries the total.
   - A tag is created only if a book gets it.
   - Removals are opt-in, and only touch tags the tool added.
   - "New books only" and its hidden per-book memory are gone.
2. **Exact-text tag identity everywhere.**
   - Every tag gets its own key.
   - One shared find-or-create, with a once-only capitals prompt.
   - Rename refuses an exact duplicate.
3. **Undo removes a tag the action created.**

## What went right

1. **Ron's data beat my theory.**
   - My first theory was capital letters in the internal tag keys. Read-only console snippets on Ron's library ruled
     it out: all 11 keys were lowercase.
   - The real flaw was that *different names make the same key* ("Non fiction" / "Non-Fiction").
   - That turned a window polish into a real data fix (exact-text tags).
2. **Testing drove the redesign.** alpha.1 polished v1. Ron's test of it showed the shape itself was wrong, which led
   to v2.
3. **Checking the code before each verdict kept finding things the discussion had missed.**
   1. The Tags filter's "Manage Tags…" wasn't missing; it scrolls out of sight.
   2. The design doc's own description of the skipped chip ("skip") didn't match the screen.
   3. **Removing and re-adding a tag by hand didn't make it yours.** The help notes would have told users a
      workaround that doesn't work.
   4. The tag-order mismatch is Manage Tags *opening* in A→Z while two other lists follow the manual order.
4. **The build list survived a compaction.** A compaction hit in the middle of the discussion. After it, the topics,
   in Ron's own words from the session record, and a build list where "a topic closes only when its line is written"
   carried the decisions. Ron: "great work".
5. **Ron's pushback improved the design repeatedly:**
   - Pin actions, but not notes.
   - The ↻ / ✓ marks (his "show me what would get removed").
   - Shared sorting for both places.
   - Undo for the window's choices.
   - "This window" is ambiguous; say "Tag from Collections".
6. **The new help-notes check passed on its first real release.** The release commit was accepted only because the
   help notes said "through release 7.24.0", and section 9 really was rewritten.

## What went wrong

1. **A "quickie" grew for three days before anyone asked whether to ship.**
   - It went to 3 alphas and a 10-topic round.
   - v2 had been shippable since alpha.3, and the TODO review sat paused the whole time.
   - Ron asked the question, not me.
   - **New rule (Law 6):** a "quick" task gets a scope checkpoint at its second alpha: *ship what works and file the
     rest?*
2. **A blanket find-and-replace rewrote history.**
   - Replacing `7.22.1` with `7.24.0` was right for 28 code comments.
   - In the design doc it also made the history claim alphas "7.24.0-alpha.1–3" that never existed, and turned my own
     sentence "7.22.1 grew into a minor release" into nonsense.
   - I caught it on review and restored the true names.
   - **Law 5:** a blanket replace judges no instance at all. List the matches first, then decide each one.
3. **Ron tested on the wrong build.** His "silent read → Read" was the 7.23.0 relay branch, which predates the capitals
   prompt. I had switched branches for the relay work without saying that localhost now served that branch.
   **Law 6:** after any branch switch, say which build localhost serves.
4. **I passed on the design doc's wrong chip description.** I copied "skip" from section 2.3 into a proposal. Ron
   caught it ("is there a blank spot?"), and the code showed a struck-through "+ Read". A design doc's description of a
   screen is a claim to check against the code (Law 2).
5. **The compaction cost the collaboration.**
   - The first reply after it recorded Ron's idea, gave no opinion, and committed without asking.
   - Fixed the same evening in the cross-project rules: the summary carries the DISCUSSION IN FLIGHT, and there's a
     build list in the design doc (Law 13, recorded at 7.23.0).
6. **The release number was set before the scope settled.** "7.22.1" was overtaken by the 7.23.0 that shipped first,
   and the work had become a minor release anyway. Cheap to fix, but it took a renaming pass.
