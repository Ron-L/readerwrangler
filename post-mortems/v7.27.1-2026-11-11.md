# Post-mortem — v7.27.1 (2026-11-11): the reset messages tell the truth

_Released 2026-11-11: squash `2877187` on main, tag `v7.27.1`, pushed to prod and dev; readerwrangler.com checked
serving 7.27.1, the new reset words and collections fetcher v3.0.2. Branch `fix/old-words` kept (alphas 1–2)._

## What shipped

1. The five reset messages no longer say "files on disk", "Import amazon-library.json" or "Export button". Each says
   what its reset removes; all share two sentences word for word ("Your saved backup files are not touched." / "To get
   everything back afterwards: File → Restore Backup… with your backup file.") and the "save a backup first" tip where
   the app still works.
2. `test/test_reset_words.py` holds the shared sentences once and lists every place still saying old words — change
   the words there first (Ron chose plain, searchable text over a shared file).
3. Download Collections' finish message names what really happened (sent to the Relay; File → Import from Relay).
4. Law 20 — hand them the action, not directions — and three tasks it starts (after the Delete key).

## What went right

1. **Ron reviewed the words against what the app does** and caught a false sentence ("your copy in the cloud is not
   touched"). Checked in the code then: the reset sends nothing, but once books are back the first change sends a full
   copy that replaces the cloud's. The sentence went; the real protection is filed (the after-reset choice).
2. **The words test earned its keep at once:** it found a sixth old line (the hint under the emergency screen's button)
   that the row-by-row review table missed.
3. **Screenshots of every place, including the one that's hard to reach** — the emergency screen, by serving a broken
   copy of the app's code (Ron's suggestion), with no temporary code in the app.
4. **Ron's pushback on structure:** a shared file for two shared sentences was indirection without payoff; identical,
   searchable text plus a test that names the stragglers is simpler and just as safe.

## What went wrong

1. **I wrote a reassurance I hadn't checked** ("your copy in the cloud is not touched") — it described the moment of the
   reset, not what the person cares about next. A message that reassures is a claim about the app's behavior.
2. **My review table missed a place** (the emergency screen's hint) — found by the test, not by reading.
3. **A scripted edit with a "\n" in it silently didn't apply** (the test's printing change) — the standing rule is the
   Edit tool for text with escapes; caught only because the output didn't change.
4. **The test harness shows only a failure's first six lines**, which hid most of the list this test exists to give —
   the test now prints its list itself.

## The bug no test would have caught

The false reassurance — no test can check that a sentence is true about the app. What can be tested is the behavior
behind it, and that belongs with the after-reset choice ("Restore from Cloud Sync…", item 6): a test that after a reset
nothing reaches the cloud until a choice is made.

## Laws touched (proposed — PRINCIPLES.md)

- **Law 12 (mechanical honesty):** a reassurance in a message is a claim about the app's behavior — check it in the code
  before writing it; "not touched" must mean not touched in the moments that matter to the person, not only at the
  instant of the action.
- **Law 20** (new today, already written).
