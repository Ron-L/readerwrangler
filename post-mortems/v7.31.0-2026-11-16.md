## What went right

1. **Two agents building at once in two copies** — four times — and the merge script combining them with no hand
   merging, every merge proven on the combined result before it landed.
2. **Ron's questions shaped the work:** "should the message offer Report?" became Report this problem on the bar;
   "I presume Copy copies the log" — it didn't, so it was made to; "not a brag point" kept the features list honest;
   "what about the other open items?" turned one fix into four small ones in the same round.
3. **A brief that said "don't use sed" failed twice — so it became a mechanism** (the gate now reads terminal
   commands), exactly the meta-principle.

## What went wrong

1. **Five one-time test failures in one week, all passing on rerun — and the last two couldn't be read**: the runner
   keeps only a failing file's filtered lines. Filed as the NEXT tooling item: keep each failed file's full output, and
   (Ron) fail browser trouble gracefully — tell machine trouble from a test failure, back off, rerun that file alone,
   say so loudly; never retry a real test failure.
2. **I misread memory figures** — quoted committed memory (Explorer "4 GB", Logitech "1.2 GB") as if it were RAM; Task
   Manager showed 455 MB and 70 MB. Corrected when Ron checked. Committed ≠ in RAM: read the column you mean.
3. **A CLAUDE.md line written for the tool, not a person** — Ron understood "less than 10%"; rewritten in plain words,
   the technical list moved to SESSION-TOOLING.md where it belongs.
4. **"Copy" didn't do what its name suggested to Ron** — fixed; a button's action should be what a person expects
   (Law 21's cousin).
