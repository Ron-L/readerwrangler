# Notes for the 7.26.0 post-mortem (draft — collected during the build, folded into the post-mortem at release)

## The false "Library repair" came back — a second check the alpha.3 fix missed (2026-11-08)

- **What:** after 7.26.0-alpha.3's Import-order fix (LOGGING.md F5 — new books reached the integrity check inside the
  load before they were filed), a false "Library repair: 22 issues fixed" still appeared. Ron recognized it as "a known
  issue" and asked for its history first.
- **The history, from the record:** alpha.3 proved and fixed the check INSIDE the load (tests failed first; TODO ✅).
  A SECOND integrity check — the "after-Import" check, added in 6.3.0, run once the screen settles — was never treated
  as a source of false alarms. I (Claude) read its code on 11-05 and walked past it.
- **How it got through the tests:** IMPORT-004 asserted "no repair" immediately after the Import returned — before the
  after-check ran; IMPORT-007 never asserted "no repair" at all; and the line was a plain `console.log`, invisible to
  the console check. It surfaced only when the logging switch (step 4) made it an **error** — the logging work paying
  for itself on its first area.
- **My first theory today was wrong** (the emptied-book-store case). Two debug lines (what the after-check sees; what
  the load set) proved the real cause in one run: an Import that found NOTHING armed the after-check in its cleanup;
  the check saw 0 books and returned without disarming; it went off mid-way through the next operation, against the
  folders from before it. Fixed in alpha.10: armed only when a library loaded, disarmed whenever it runs.
- **Laws:** 3 (instrument → prove → fix → prove — the theory would have built the wrong fix); 4 (two checks for one
  event; the second break in the same family); 17 (an armed flag that outlives its operation is an illegal state); the
  testing rule "test the class" — every Import scenario now asserts "no repair, after the screen settles", and IMPORT-004
  proves the after-check still runs (shown to fail with Import's arming removed — its first form didn't catch that).
- **The failure to name in the post-mortem** (Ron): the version of me that fixed F5 on 11-05 didn't look for the other
  checks of the same thing, and didn't make every Import test assert the outcome after settling.
