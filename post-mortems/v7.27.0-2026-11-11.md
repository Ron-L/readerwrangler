# Post-mortem — v7.27.0 (2026-11-11): faster loading

_Released 2026-11-11: squash `c8a62c0` on main, tag `v7.27.0`, pushed to prod and dev; readerwrangler.com checked
serving 7.27.0 and its three built files. Branch `feature/faster-loading` kept (alphas 1–5). Also covers the tooling
done on main between 7.26.0 and the branch (the backlog report's fixes, the removed-task check)._

## What shipped

1. **The app built ahead of time.** The page compiled readerwrangler.js / mobile.js in the browser on every load —
   measured ~50 s on Ron's PC, the same with 23 books or 3,270. `tools/build.py` now compiles them into `dist/` with the
   Babel the page loaded (7.29.7, pinned in `tools/build/`; every statement keeps its source line); the page loads plain
   scripts. 0.5 s to the app.
2. **The styles built ahead of time.** Three pages loaded Tailwind's in-browser builder; `dist/tailwind.css` (the same
   Tailwind 3.4.17) replaces it. Every element's computed style compared, builder vs built, on 8 app screens, the phone,
   the reset and security pages: no difference.
3. **Nothing to remember:** `serve.py` rebuilds on demand; a commit check refuses a stale `dist/`; the version guard now
   checks cache-stamps in every page that loads a file.
4. **The folders sooner:** the desktop no longer reads every cover copy into memory at start (it hadn't drawn from them
   since 5.0.0 — they served one image) and clears them once; a load saves the books only when it changed one. Folders
   on screen with Ron's library: 4.4 → 1.6 s measured; Ron counts ~2–2.5 s.
5. **Tooling:** `tools/time_load.py`; the test driver blocks Amazon and real relays; the backlog report counts real work
   only, finds ✅ on any branch, follows each task's own dates, marks events and releases; a commit check refuses
   removing a TODO task silently (it replays the commit that lost one).
6. **Words:** the reset page's panel, the security page's note, the splash's "busy compiling" note removed.

## What went right

1. **Measure before and after, every step** — and measure the pieces when a fix disappoints (the first "changed?"
   comparison cost as much as the save it removed; 263 ms vs 114 ms a pass, found and fixed in one run).
2. **Ron's experiment-first call** ("disable the loading of our unused cache first to confirm it speeds up and still
   loads") — cheap, decisive, and it made the removal safe.
3. **A style comparison by computed values**, not by eye: every element on every screen, builder vs built — the kind of
   check that proves "looks identical" instead of hoping.
4. **Shown it can fail:** every new test was run against its own bug; three hollow ones were caught that way (COVERS-001
   waited on a promise Playwright never awaited; BKLG-013 passed through the rename matcher; BKLG-005 passed through
   the branch evidence).
5. **Ron's structural ideas:** one common save function for the 60 callers; real work only in the backlog; events named
   on the charts; the order of work is the TODO's order.

## What went wrong

1. **My load time measured the wrong moment, under the wrong conditions.** The "All Books" count appears before the
   folders, and a fresh test browser has no cover copies; Ron's screen took ~7 s while I reported 1.3. His count was
   right. The tool now times "folders on screen" after filling the cover cache.
2. **The driver recorded forbidden hosts instead of blocking them**, so my timing runs fetched Ron's library's covers
   from Amazon's image server (~3 sessions) — a rule written down and logged, but not enforced. Now blocked.
3. **Nine months of dead work on every load:** since 5.0.0 the desktop never drew from its cover copies, yet every
   load read them all before showing the folders. Nobody saw it because nothing measured what each step of the load
   was for.
4. **7.26.0 fixed one of four listed places.** The Reset App task listed all four places of the old reset words; the
   fix touched place 2 and its note read as if done. The site map existed — the fix didn't work from it.
5. **A list of one page:** the version guard checked stamps only in readerwrangler.html; the reset page's were never
   checked (generalized).
6. **A generic ignore rule hid the build:** `.gitignore`'s "build outputs" (`dist/`, `build/`) hid `dist/` and
   `tools/build/`, so serve.py refused the page's own script; the first try loaded nothing (caught by the tests).
7. **An unmeasured number in a commit message** ("down from ~12 min" for the old tier-2 run — never timed).

## The bug no test would have caught

1. **The driver's Amazon leak** — no test checked that a request to Amazon is *refused* (only that none was made by the
   fixture). Proposed: DRV-004 — a page request to Amazon's image server gets the stand-in, and one to amazon.com is
   refused. **Written with Ron's yes.**
2. **The ~7 s to Ron's folders** — no test loads a library at Ron's scale with a full cover cache. The screen tests use
   23 books; the 3,270-book copy is private. Filed against "Generated test libraries" (a generated 3,000-book library
   makes a load-time test committable).

## Laws touched (proposed — PRINCIPLES.md)

- **Law 8:** measure the moment the person sees, under the person's conditions (their library's size, their caches
  full); when their count disagrees with your number, your end point is wrong — Ron's ~7 s vs my 1.3 s.
- **The meta-principle, reprised:** a rule that's only recorded gets broken — the driver logged Amazon requests and let
  them through; enforce at the chokepoint (it now blocks).
- **Law 5:** a site map in a task doesn't fix the class — work from it and check each place off; 7.26.0 fixed one of
  four listed places.
- **Law 15 (chase every alarming number), widened:** time every step of a path that runs on every load, and ask what
  each step is for — the cover copies served one image and cost seconds for nine months.
