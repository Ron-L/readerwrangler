# Post-mortem — v7.25.0 (2026-10-31): signed writes

_Released 2026-10-31: squash `7132a84` on main, tag `v7.25.0`, pushed to prod and dev; both relays redeployed from
main at worker 7.25.0 (dev `f54d5622`, prod `df37032b`). Branch `feature/signed-writes` kept. Design:
docs/design/RELAY-SECURITY-PLAN.md, Phase 3._

## What shipped

1. **Signed writes.** The Channel ID now only addresses a mailbox. Every write, delete and revoke is signed with a
   write key derived from the passphrase (never the encryption key): HMAC over the time, the method + address, and the
   body's SHA-256 — or, for big encrypted parts, their size (their bytes are covered by the signed manifest's SHA-256,
   checked by every reader, plus AES-GCM). The relay learns a channel's key at its first save and then refuses anything
   unsigned, wrongly signed or more than 5 minutes off; a PC clock that's off is corrected by one retry.
2. **Finished copies' parts are write-once**; **revoke is signed** (an ID holder can no longer lock an owner out).
3. **Readers require the checksum** for copies minted from 2026-10-31 (one rule, `verifyChecksum`, at all four read
   sites). The fallback to a good copy already existed.
4. **The shared-numbers check** now also compares the signature format between app and relay.
5. Shipped with it (main's commits since 7.24.0): the published-credentials fix (the organized demo library file),
   the private-value commit checks + history scan, the relay reminder hook, the Cloud Sync naming decision, and the
   TODO review's work.

## What went right

1. **Ron's questions were the outside review.** My first sketch was a fixed proof token. Ron: "Any man in the middle
   could capture that and reuse it" → per-request signatures. Ron: sign only the channel + time? → the time does the
   replay work (kept), but the operation must be signed too. Ron: nonces / sequence numbers? → rejected with reasons
   (KV write budget, eventual consistency, two writers). Ron: "garbage of the same length" for size-only parts → the
   reader's signed-manifest checksum + write-once. Each round improved the design; the doc records all five.
2. **A mechanism found what discipline missed.** The leaked credentials weren't found by care — by a structural
   look (is any committed JSON backup-shaped?). Now a commit check refuses them by shape.
3. **One gate, one signer.** The relay checks every non-GET channel route in front of `route()` (a future route is
   covered without being listed); the app signs through `signedFetch`. A two-pivot comb found five older direct writes
   that would have bypassed it.
4. **Look backward first:** the reader fallback and the full revoke wipe already existed — checked before building,
   so neither was built twice (and a TODO item was corrected).
5. **Tests that can fail:** an independent signer in the test (not the client's code), a hand-made correct signature
   accepted, and a control copy served beside the stripped-checksum copy refused.
6. **Test-on-local-first:** Cloudflare's own dev server with simulated storage — the whole design was proven before
   any real relay changed.

## What went wrong

1. **The credentials leak itself** (since July): a backup-shaped demo file committed with its `relay` block filled.
   Nothing checked for it. Now one thing does.
2. **I stopped 14 processes, not one.** To stop the local relay I matched processes by command-line text
   (`*wrangler*dev*--local*`); it also matched the shells that launched it and the stop command itself. All were mine;
   Ron's server was unaffected. Rule: stop a process by its exact id.
3. **The existing relay test "failed" 7 times** after signing — the protection working (its deliberately broken states
   were unsigned writes on a now-registered channel). Read before fixing: the fix was in the test (sign its raw writes
   through the one signer), not the code.
4. **Found, not fixed (filed):** every import with new books logs an integrity "repair" — the check runs before the
   import files them (Ron flagged it; TODO "Import: new books are filed before the integrity check…").

## Laws touched (PRINCIPLES.md)

- **Law 5:** a secret is a class too — find it by its shape, not a list; a blanket stop (matching by text) judges no
  instance, like a blanket replace — act on exact identities.
- **Law 3:** a test that fails because the protection works — read the failure before "fixing" either side.
- **Law 12:** an alarm that fires on the normal path is noise; it must know the difference (the integrity log).
